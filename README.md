# Sanad سند

Question answering over Saudi law, in Arabic, with the article it rests on.

Work in progress. Done so far: retrieval baselines (step 1), retriever fine-tuning (step 2), and a 7B language model that answers from the retrieved law with a citation and says so when the law is not there (step 3). Running: step 4, training on plain-language rewrites of the questions. Next: a service and a demo.

**Main finding so far.** Training on LLM-written questions, which copy the wording of the law, makes both the retriever and the answering model better on more questions of that kind and worse in a different way on questions people actually ask. It happened twice, in two different models.

Not legal advice. The system is a study of retrieval and grounded answering, not a source of legal guidance.

## Data

Downloaded when the code runs, never stored in this repository.

- **ArabLegalEval** (THIQAH and KAUST, [github.com/Thiqah/ArabLegalEval](https://github.com/Thiqah/ArabLegalEval)): 10,583 multiple-choice questions written by GPT-4 and Claude 3 Opus from 5,725 passages of Saudi law. No licence is stated in that repository, so it is used for evaluation only.
- **Najiz QA**, in the same repository: 79 expert-verified questions from public FAQs, each with the legal text that answers it.
- **ALARB** (THIQAH, [huggingface.co/datasets/HarethahMo/ALARB](https://huggingface.co/datasets/HarethahMo/ALARB), Apache-2.0): about 13,000 Saudi commercial court cases with the statute articles each one cites.

Questions are split 70/15/15 by the passage they were written from, so a passage is never the answer to a training question and a test question at once. The passages behind the Najiz questions are all kept out of training.

The ArabLegalEval questions were generated by a language model reading the passage, so they repeat its wording and favour word-matching retrievers. The 79 Najiz questions were written by people and are the harder, more honest test.

## Step 1: retrieval baselines

Corpus: 6,565 passages of Saudi law. Recall@1 / @10 in percent and MRR@10. Timings are per query on a Kaggle T4, corpus already encoded.

| Retriever | Test questions (1,661, LLM-written) | Najiz questions (79, human-written) |
|---|---|---|
| BM25, normalised and lightly stemmed Arabic | 78.6 / 94.3 / 0.843 | 40.5 / 69.6 / 0.491 |
| multilingual-e5-base | 74.4 / 94.3 / 0.815 | 63.3 / 87.3 / 0.708 |
| multilingual-e5-large | 76.3 / 95.3 / 0.831 | 63.3 / 91.1 / 0.718 |
| bge-m3 | 76.0 / 95.2 / 0.831 | 59.5 / 88.6 / 0.705 |
| BM25 + bge-m3, reciprocal rank fusion | 82.4 / 96.9 / 0.878 | 59.5 / 79.7 / 0.651 |
| the same, reranked by bge-reranker-v2-m3 | **84.0 / 98.3 / 0.898** | 63.3 / 91.1 / 0.724 |

What this shows:

- On the LLM-written questions, word matching is strong: BM25 beats every embedding model at Recall@1, because the questions reuse the wording of the passage they came from.
- On questions people actually asked, BM25 falls to 40.5% and the embedding models reach 59.5 to 63.3%. Fusing BM25 in makes these questions worse, not better; the reranker only wins back what the fusion lost.
- 79 questions is a small set: one question is 1.3 points, so the differences between embedding models there are not meaningful.

The fine-tuning in step 2 starts from multilingual-e5-base: on human questions it matches the larger models at a third of the size, which matters for serving.

## Step 2: fine-tuning the retriever

multilingual-e5-base, fine-tuned with in-batch negatives and one mined hard negative per pair, 2 epochs. Recall@1 / @5 / @10 and MRR@10, the retriever alone.

| Training data | Test (LLM-written) | Najiz (human-written) |
|---|---|---|
| none (starting model) | 74.2 / 91.0 / 94.3 / 0.815 | **63.3 / 86.1 / 87.3 / 0.715** |
| ArabLegalEval training questions (7,325) | **82.1 / 95.1 / 97.4 / 0.876** | 58.2 / 70.9 / 81.0 / 0.648 |
| the same + ALARB court cases (10,608 facts → cited article) | 80.5 / 94.1 / 96.9 / 0.865 | 59.5 / 67.1 / 78.5 / 0.635 |

Fine-tuning gains 8 points of Recall@1 on questions like the training ones and loses on human questions: Recall@5 falls from 86.1% to 70.9%, which is 12 of 79 questions. The selection rule (best dev MRR) picks the fine-tuned model, because the dev set is LLM-written too. Steps 3 and 4 use the starting model instead, because the assistant is for people.

## Step 3: the answering model

Retriever: multilingual-e5-base, top 3 passages. Both models in 4-bit on a T4.

**Multiple choice** (400 test questions, four options; accuracy in %):

| Model | Closed book | Top 3 retrieved passages | Gold passage only |
|---|---|---|---|
| ALLaM-7B-Instruct | 67.3 | 93.5 | 97.8 |
| Qwen2.5-7B-Instruct | 65.8 | 93.5 | 97.8 |
| ALLaM-7B-Instruct + QLoRA | 67.0 | **96.5** | 98.8 |

Retrieval is worth 26 points. The fine-tuning does not add legal knowledge (closed book is unchanged) but makes better use of the passages it is given. The gold passage is in the top 3 for 87% of these questions, so most remaining errors are retrieval misses.

**Grounded answers** (answer in Arabic with a citation such as [2]; "unanswerable" = the same question with the gold passage removed from the context):

| | Cites the gold passage | Says "not found" when the law is missing | Says "not found" although the answer is there | Answer F1 |
|---|---|---|---|---|
| ALLaM, test | 27% | 16% | 0% | 0.42 |
| Qwen, test | 90% | 46% | 1% | 0.44 |
| **ALLaM + QLoRA, test** | **93%** | **84%** | 7% | **0.80** |
| ALLaM, Najiz | 26% | 18% | 2% | 0.46 |
| Qwen, Najiz | 76% | 33% | 3% | 0.43 |
| **ALLaM + QLoRA, Najiz** | 55% | **86%** | **44%** | 0.47 |

QLoRA (rank 16, 1,600 examples, 25% of them with the gold passage removed and the target "not found") fixes the two failures that matter most in a legal assistant: before it, ALLaM made up an answer for 84% of questions whose law it had not been given, and rarely said where its answer came from. On LLM-written questions it now cites the right article 93% of the time.

On human questions it overcorrects: it says "not found" for 44% of questions whose answer is in front of it, because people do not use the wording of the law and the model learned that missing wording means a missing answer. Step 4 retrains on plain-language rewrites with fewer "not found" examples.

Najiz answer F1 understates quality: the reference answers are whole paragraphs, while the model answers in a sentence, so a correct short answer scores low.

## Step 4: training on how people actually ask

Qwen2.5-7B rewrote 2,400 training questions in the plain style of a citizen (it saw only the question, never the passage); 2,396 rewrites were usable. They are moderate paraphrases, with some drift in meaning.

**Retriever** (Recall@1 / @5 / @10 / MRR@10; each recipe trains on 2,400 pairs, the last on both sets):

| Training data | Retrieval | Test | Najiz |
|---|---|---|---|
| none (starting model) | dense | 74.2 / 91.0 / 94.3 / 0.815 | **63.3 / 86.1 / 87.3 / 0.715** |
| none (starting model) | hybrid | 80.7 / 94.8 / 96.6 / 0.866 | 55.7 / 75.9 / 81.0 / 0.639 |
| original questions | dense | 76.1 / 91.0 / 94.6 / 0.826 | 54.4 / 72.2 / 78.5 / 0.622 |
| plain-language rewrites | dense | 73.8 / 89.5 / 92.9 / 0.806 | 55.7 / 73.4 / 77.2 / 0.628 |
| original + rewrites | dense | 77.3 / 93.0 / 96.0 / 0.840 | 59.5 / 73.4 / 81.0 / 0.660 |
| original + rewrites | hybrid | **81.8 / 94.6 / 97.0 / 0.873** | 51.9 / 73.4 / 81.0 / 0.609 |

Rewriting the questions does not fix the retriever. Every fine-tuned recipe loses at least 12 points of Recall@5 on human questions, rewrites included. The rewrites still come from an LLM, and the passages they point to are the same LLM-chosen passages, so the model learns the benchmark rather than people. Adding BM25 also hurts on Najiz, because people rarely use the words of the law. The assistant keeps the starting e5 model with dense retrieval; the honest way to improve it is real user questions, which this project does not have.

**Answering model**, ALLaM fine-tuned again on the rewritten questions with 12% "not found" examples instead of 25%:

| | Cites the gold passage | Says "not found" when the law is missing | Says "not found" although the answer is there | Answer F1 |
|---|---|---|---|---|
| 25% "not found", original questions (step 3), test | 93% | **84%** | 7% | 0.80 |
| 12% "not found", rewrites, test | **96%** | 40% | **2%** | 0.81 |
| 25% "not found", original questions (step 3), Najiz | 55% | **86%** | 44% | **0.47** |
| 12% "not found", rewrites, Najiz | **77%** | 46% | **11%** | 0.37 |

Multiple choice with retrieved passages: 95.0% on test (step 3 adapter: 96.5%).

On human questions the false "not found" rate falls from 44% to 11%, and the model now cites the right article for 77% of them instead of 55%. The price is the other failure: with the relevant article removed, it answers anyway more than half the time, usually from a neighbouring article. The share of "not found" examples is a dial between refusing too often and answering too readily. Part 6 trains a third point on the dial (18%).
